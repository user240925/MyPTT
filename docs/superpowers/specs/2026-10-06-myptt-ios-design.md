# MyPTT 設計規格

日期：2026-10-06

## 1. 目標

以開源專案 [PCMan Windows](https://github.com/pcman-bbs/pcman-windows) 為參考，打造一個可在 iPhone 上執行的 PTT 連線 app。

- 使用對象：作者本人自用，日後可能開源。
- 連線目標：只連 PTT，網址固定為 `wss://ws.ptt.cc/bbs`。
- 成功標準：在 iPhone 上能登入 PTT，以觸控完成瀏覽看板、閱讀文章、發文與推文。

## 2. 限制與前提

- **開發環境只有 Windows。** 程式碼在 Windows 上完成並推上 git，之後借用 Mac 拉取專案、編譯、安裝到 iPhone。借用時間有限，所以主要的開發與除錯必須在 Windows 上完成。
- **授權為 GPL。** PCMan 以 GNU GPL 第 2 版釋出，本專案會移植它的邏輯，屬於衍生作品，因此同樣以 GPL 第 2 版釋出。這與自用及開源相容，但與 App Store 上架有衝突；本專案不以上架為目標。
- **PCMan 原始碼不放進本 repo。** 需要時放在 repo 以外的資料夾參考。

### 已實測確認的連線條件（2026-10-06）

| 項目 | 結果 |
|---|---|
| 連線必須帶 `Origin` 標頭 | 不帶會被拒絕（HTTP 403） |
| `Origin: app://pcman`（PCMan 的做法） | 連線成功 |
| `Origin: https://term.ptt.cc` | 連線成功 |
| 資料格式 | WebSocket 二進位訊息 |
| 文字編碼 | Big5，不是 UTF-8 |

## 3. 技術選擇

採用 **Flutter（Dart）**。

理由：Windows 桌面版與 iOS 版共用同一套繪製引擎，在 Windows 上驗證過的畫面與手勢到 iPhone 上落差最小，iOS 編譯流程也成熟，適合 Mac 時間有限的情況。

曾考慮但未採用：

- .NET MAUI：語言較熟悉，但 iOS 工具鏈對 Xcode 版本要求嚴格，在借來的 Mac 上風險較高。
- 網頁技術加 Capacitor：瀏覽器無法自訂 `Origin` 標頭，需要寫 iOS 原生外掛，而該部分在 Windows 上無法測試。

## 4. 架構

分成四層，上層只依賴下層。下面三層為純 Dart，不引用任何 Flutter 介面套件，可在 Windows 上以單元測試驗證。

| 層 | 職責 | 參考的 PCMan 來源 |
|---|---|---|
| 1. 連線 | 以 WebSocket 連 PTT，收送位元組，回報連線與斷線 | `Websocket.cpp`、`ConnIO.h` |
| 2. 終端機核心 | 把收到的位元組解成畫面狀態 | `TelnetConn.cpp`、`RFC854.h`、`Ucs2Conv.cpp` |
| 3. 畫面辨識 | 讀取畫面狀態，判斷目前是哪種畫面 | 無 |
| 4. 介面 | 繪製畫面狀態，接收觸控與鍵盤，轉成按鍵送回第 1 層 | `TermView.cpp`（僅繪製規則） |

### 4.1 連線層

- 介面為：連線、送出位元組、關閉，以及三個事件：已連線、收到資料、已關閉。
- 連線時帶 `Origin: app://pcman`。
- 可替換。測試時換成播放預先準備好的位元組資料的假連線。

### 4.2 終端機核心

- Telnet 協商。
- ANSI／VT100 控制碼解析：游標移動、清除、捲動區域、插入與刪除行、顏色與屬性。
- 80×24 的格子緩衝。每格記錄字元、前景色、背景色、高亮、閃爍，以及全形字的左右半邊資訊。
- Big5／UAO 與 Unicode 的雙向轉換，集中在單一模組。app 內部其餘部分全程使用 Unicode。
- 支援雙色字：一個全形字的左右半邊可以有不同顏色。
- 輸出的是畫面狀態，不是畫好的圖。
- 遇到無法辨識的控制碼則略過；遇到沒有對應的 Big5 字碼則以替代符號顯示。兩者都不中斷處理。

UAO 對照表不在 PCMan 的 repo 內（由其 `UAOTabGen` 工具產生），本專案需自行產生或取得對照表並打包進 app。

### 4.3 畫面辨識

第一版只定義介面與所在位置，不實作任何辨識規則。第一版所有畫面一律以終端機方式呈現。

保留這一層的目的是日後可針對特定畫面（例如文章內容）提供手機原生的閱讀介面，而不必改動終端機核心。

### 4.4 介面

見第 5 節。

## 5. 手機介面與操作

### 5.1 畫面

1. **登入頁**：輸入帳號密碼，可選擇記住。密碼存於 iOS 鑰匙圈。
2. **終端機頁**：全螢幕顯示 PTT 畫面，連上後自動送出帳密完成登入。

### 5.2 終端機頁版面

由上而下：終端機畫面、常用按鍵列、系統鍵盤（需要時才出現）。

- 終端機畫面寬度貼齊螢幕，可雙指縮放與拖曳。橫向時自動放大。
- 每個字畫在固定格子裡，不依賴字型寬度對齊，使用系統字型。
- 框線與色塊字元以圖形繪製，確保 ANSI 圖案無縫相接。
- 支援 16 色、高亮、閃爍、雙色字。

### 5.3 手勢

| 手勢 | 對應按鍵 | 用途 |
|---|---|---|
| 向右滑 | ← | 返回上一層 |
| 向左滑 | → | 進入 |
| 向上滑 | PageDown | 下一頁 |
| 向下滑 | PageUp | 上一頁 |
| 點一下網址 | 無 | 開啟連結 |
| 點一下其他位置 | 無 | 叫出或收起鍵盤 |
| 長按 | 無 | 選取文字並複製 |

### 5.4 按鍵列

方向鍵、Enter、PgUp、PgDn、Home、End、Esc、Tab，以及 Ctrl 鍵。Ctrl 鍵按下後與下一個字母組合送出。按鍵列可左右捲動。

### 5.5 文字輸入

- 使用系統鍵盤與輸入法。選字完成後才轉成 Big5 送出，組字過程中不送。
- 輸入內容含有無法轉成 Big5 的字（例如表情符號）時，送出前提示「有 N 個字 PTT 不支援，將以 ? 取代」，再以 `?` 取代後送出。

### 5.6 連線行為

- **回到前景自動重連**：iOS 會在 app 進入背景後暫停它，連線會中斷。回到前景時自動重新連線並登入一次。使用者會回到主選單，而不是原本的位置。
- **防閒置**：在前景時定時送出不影響畫面的按鍵，避免被踢下線。

### 5.7 第一版不做

- PCMan 的分頁、多站台管理、我的最愛、滑鼠手勢、自動回覆、搜尋外掛、ANSI 編輯器。
- 點一下列表中的某一列直接進入（需要畫面辨識）。
- 顯示超過 24 列。
- 連線到 PTT 以外的站台。

## 6. 錯誤處理

| 狀況 | 行為 |
|---|---|
| 連不上 | 顯示原因與重試按鈕，不自動無限重試 |
| 連線中途斷線 | 畫面保留最後內容並變暗，顯示「已斷線」，提供「重新連線」與「繼續瀏覽」兩個選項 |
| 選擇繼續瀏覽 | 畫面恢復正常亮度，可縮放、拖曳、選取複製、開啟網址。上方保留「已離線」提示與重連按鈕。按鍵列與鍵盤輸入停用。只能檢視斷線當下的那一個畫面 |
| 回到前景發現已斷線 | 自動重連並登入一次；失敗則比照「連不上」 |
| PTT 自己的提示（帳密錯誤、重複登入等） | 不特別處理，照常顯示，由使用者操作 |
| 自動登入等不到預期的提示 | 逾時後停止自動送出，交還使用者手動操作 |

原則：核心層遇到異常資料一律不當機。

## 7. 測試

- **終端機核心**：以準備好的位元組資料做單元測試，比對最後的格子內容。涵蓋游標移動、清除、捲動區域、顏色、雙色字，以及全形字被切在兩個封包之間的情況。
- **Big5 轉換**：雙向測試，包含 PTT 常見的特殊符號與日文假名。
- **連線層**：開發時對真實 PTT 手動驗證，不寫依賴外部服務的自動測試。
- **介面**：在 Windows 桌面版手動操作，視窗調成手機比例。
- 從 PTT 實際錄下的資料不進 git，因為會包含帳號與他人文章。repo 內的測試資料為手寫或去除個資後的內容。

## 8. 留到 Mac 上驗證的項目

以下四項在 Windows 上無法驗證，各自集中在單一檔案，方便到 Mac 後調整：

1. iOS 系統鍵盤與中文輸入法的行為，以及鍵盤彈出時的版面。
2. 鑰匙圈儲存。
3. 進入背景與回到前景的重連時機。
4. 實際手指操作的手勢手感與字體可讀性。

repo 內附 `docs/ios-build.md`，說明在 Mac 上的步驟：安裝 Xcode 與 Flutter、拉取專案、設定簽章用的 Apple ID、連接 iPhone 編譯安裝，以及上述四項的檢查清單。

## 9. 實作順序

1. 安裝 Flutter，建立專案，確認 Windows 版可執行。
2. 連線層。
3. 終端機核心與 Big5 轉換，搭配單元測試。
4. 終端機畫面繪製。
5. 手勢、按鍵列、文字輸入。
6. 登入頁、自動登入、重連、防閒置、斷線後繼續瀏覽。
7. iOS 建置說明文件。
